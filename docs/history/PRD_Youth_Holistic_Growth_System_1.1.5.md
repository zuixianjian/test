# 终身岛民 · 青少儿全人成长与自主进化系统

产品需求与实现契约，版本 **1.1.5**，更新日期 **2026-11-14**。

本版统一数据来源、页面职责、任务调度、验收规则、跨模块回写与恢复边界。旧版保存在 `docs/history/PRD_Youth_Holistic_Growth_System_1.0.15.md`，不再作为当前字段或状态机契约。高保真外观以 `high_fidelity_ui_preview.html` 为参考；规则由与插件共享的 `src/core/domain.mjs` 和 `src/runtime/closedLoop*.js` 实现。组件画板中的题目、人物与数值为样式样例，不得成为用户事实。

## 1. 定位、边界与基本原则

面向7～15岁青少儿，以真实付出、客观证据和亲子共同确立的规则培养自主成长能力。禁止经验值、虚拟金币、积分等级，藏金屋只维护真实独立收支，不与学习或行为对赌，也不产生财商养成勋章。

只有一个主视口活跃：**执行中心**负责执行与交付；**规划沙盘**负责场馆、项目、节点及标准编排。四大规划场馆为校史馆、武道馆/兴趣屋、思辨馆、修身阁，可新增 `custom-*` 场馆。藏金屋、个人行为规范、每日随记、成就馆是独立模块，不提供虚构的甘特规划。

完整闭环定义：输入有主体和来源ID → 业务校验通过 → 修改领域实体 → 保存可恢复 → 更新日/周/月及其他投影 → 可以回到原项目、节点、记录或附件。按钮打开页面或出现成功提示不等于闭环。

### 2.2 节点完整结构

```typescript
type NodeType = 'goal'|'drill'|'habit'|'review'|'custom'|'text';
type Frequency = 'once'|'daily'|'weekdays'|'weekly';
interface WorkNode {
  id: string; projectId: string; pavilionId: string; title: string; // 标题2～30字
  nodeType: NodeType; isCheckinNode: boolean;
  status: 'pending'|'completed'|'archived'; // 历史验收摘要；每日就绪由TaskInstance决定
  plannedDate: string; frequency: Frequency; dependencies: string[]; weight: number;
  canvasPosition: {x:number;y:number};
  groupId: string|null; groupRoot: string|null;
  createdAt: string; updatedAt: string; executionRecords: string[];
  achievementId: string|null; readCount: number; lastReadTime: string|null;
  cardPayload: {
    description: string; plannedMinutes: number; evidenceType:'none'|'text'|'photo'|'video'|'audio';
    metrics: {id:string;name:string;targetValue:string;unit?:string}[];
    checklist: {id:string;title:string;required:boolean}[];
    improvementList: {id:string;actionItem:string;isChecked:boolean;derivedNodeId?:string}[];
    customFieldsSchema: {key:string;label:string;type:'text'|'number'|'boolean'|'date';required:boolean}[];
    textContent:string; acceptanceCriteria:string; targetDeadline:string|null;
  };
}
```

`review`是规范枚举；旧`reflection`/`card-review`/`card-reflection`仅作为迁移输入别名。`id`是规范主键，旧`nodeId`只在迁移时读取。前置依赖只引用同项目真实可执行节点；普通关联边不阻塞。前置/依赖/阻塞边的起点是前置、终点是被限制节点，类型切换和删边同步dependencies；禁止循环依赖。周期前置按同一计划自然日核验，一次性前置通过后可解锁后续实例。

规划卡内维护标准、列表和依赖，不放“立即打卡”按钮。目标卡“记录已验收成果”未有验收记录时打开成果验收页，不直接生成勋章。所有实际交付发生在执行态；标准只读。

### 2.4 执行记录

每次校验通过生成不可重复的CheckinRecord，保留 `metricValues/metrics`、`checklistResults`、`improvementList`、`customFieldValues`、`reflection`、`focusSeconds`、附件及sourceSnapshot标准快照。相同taskInstanceId重复提交返回原记录。源节点仅保存记录ID引用，不能用最近一次记录覆盖全部历史。撤销规划、删除节点或调整后续标准不删除或改写已发生事实。

`date`是实际提交的自然日；`scheduledDate`是计划日。逾期补做仍保存实际发生日期，不自动伪造昨日打卡；原计划实例可因此完成，连续天数只计算实际日期。

## 3. 调度、状态与统计

### 3.1 任务状态机

未归档项目中需要执行的节点，根据plannedDate、frequency及项目结束日产生实例：一次性只产生一个；每日/工作日按自然日；每周取首次计划日的同一星期。文本节点不生成任务。

- `scheduled`：未来计划日。
- `blocked`：前置未通过或引用缺失；在执行入口明确说明，不开放提交。
- `ready`：今日且前置完成。
- `overdue`：计划日已过去，尚无有效执行记录；不等待换周才判断。
- `completed`：对应实例已有通过验收记录；契约实例须经家长核准。

日视图展示今日可执行与已完成实例及活跃契约；周/月读取同一个调度结果。月日历另标“实际交付”数量，详情列明计划日与实际日；日期相册只显示该日保存的真实附件。所有打开入口传递taskInstanceId，不从场馆名猜任务。执行池可由领域数据完全重建，HTML和week-board都不是第二份事实源。

悬赏实例主键为`bounty-<bountyId>@<acceptedDate>`，兑现前按到期日放入周/月，但在揭榜后持续出现在日执行池。兑现后归入verifiedDate，历史已兑现悬赏不再计入后续日期的今日分母。其有效执行由家长核准的记录提供，孩子上传证据本身不等于兑现。

### 3.2 项目状态与进度

项目验收进度只聚合需要执行的节点，不把自然日方格当总任务数。一次性节点比例为0或1；周期节点比例为已完成计划实例/全周期计划实例。项目百分比为各节点完成比例按weight加权；默认weight=1。所有执行节点的计划实例均完成且至少有一个执行节点才可标“已完成”。

已完成节点数/节点总数与已完成实例数/实例总数分别保存。甘特日期方格展示当日真实执行记录，不替代验收进度；点击打开只读原始记录与附件。

状态优先级：已归档 → 全部完成 → 开始日前5天以上待规划 → 开始日前5天内待执行 → 周期内进行中 → 结束后未完成待执行。不允许手工把未完成项目归档。调整计划与归档立即重算所有任务投影。

### 3.3 连续坚持与履约率

- 有效日：至少一条按所属卡型规则通过验收的真实执行记录，且当日无共同确认违约。旧版没有新标准验收标记的记录保留为历史，不自动包装为已核验事实。
- 当日尚未完成不立刻打断昨日连续；隔日仍无有效记录才断开。批准保护的日期维持连贯但不增加天数。阅读、设置、记账与浏览不增加坚持。
- 每月保护额度2次，保存月份、批准原因与时间；不允许保护已有效打卡、已保护或有违约的日期。额度表示上限，used表示该月已用次数。
- 综合履约率＝`max(0,min(100,60×规划完成比+40×契约/修身完成比)-5×共同确认违约次数)`。
- 分母为领域调度中的当日应履约任务；blocked、未来、取消及归档项目不进入。无任务的该分项按1计，界面同时显示0项而非虚构完成数量。悬赏按照自身ID核验，不受当前展示哪个榜单影响。
- 历史累计专注由通过验收的真实秒数求和。周视图完成率是选中周实例完成数/应完成实例数，与综合履约率分开命名，不混称。

项目全部执行节点验收后自动生成一次项目结业荣誉，保存当时节点数量及来源记录ID列表。连续有效日首次达到19天自动生成一次真实践行里程碑，保护日不增加有效天数。二者以milestoneKey幂等；后续增加规划不改写历史达成快照。目标专项成果仍须通过指标验收。

### 4.2 规划沙盘、二级甘特与三级脑图

1.1.5移动端：插件视图根节点、内容区和叶子容器在运行时启动前设置宿主使用的`data-ignore-swipe`边界；根节点阻止触摸事件继续冒泡，但不取消浏览器默认滚动。插件内画布手势、卡片纵向滚动、表单和显式左右栏按钮仍可用，插件外宿主手势不受影响；关闭/读取失败时还原边界。保存报错不得跳过视图或插件卸载清理。

路线SVG实际范围必须覆盖节点和线路，不能依靠1px画布外的溢出命中。线路从两端各自的关联度选择边界端口，端口通道被挡时尝试其他边界，通道不足时逐级缩小安全间距；找不到合法路线时显示可编辑的受阻提示，不退回穿过节点的直角线。相同方向重复选择不再反转，保持选中态；拒绝反转后重复同向边和循环包含关系。子级跟随只沿包含/派生关系，不沿任务前置或一般关联传播。

1.1.4导航地图参考本地a-my-island 1.6.0的缓存投影及视口更新机制，规划与脑图共用220×130的SVG坐标系。地图与按钮在右下角并排显示，并避让规划页底部工具栏；执行态隐藏规划导航。地图节点来自实际可见场馆或当前项目卡片，大小采用真实卡片尺寸，按类型着色，不把临时连线控件或历史项目画成节点。

投影范围包括节点边界和当前世界视口，加入至少80世界单位或跨度6%的留白；普通平移/缩放只按帧更新视口框，不逐事件重建节点。节点增删、位置或尺寸变化、项目切换及适应/还原重新计算地图几何。视口框拖动全程使用按下时的投影和相机，不因范围变化漂移；若视口移出地图，停止操作约180ms后重投影，恢复可见范围。

点击或轻触地图将对应世界点居中；拖动红色视口框只平移画布，不缩放或触发第二次居中。指针换算使用SVG实际屏幕矩阵，兼容外层缩放和SVG留白。触摸取消、失焦、Esc、关闭地图、切换项目均结束拖动；地图内滚轮不误操作主画布。聚焦地图后可用方向键平移、Home适应画布。

`DOMAIN_STATE.navigation.planning.collapsed`和`navigation.projects[projectId].collapsed`分别保存展开状态，随完整领域提交或独立设计IndexedDB保存。旧数据默认规划地图收起、项目地图展开。按钮同步`aria-expanded/aria-controls`；空项目不显示虚构节点。导航只修改呈现状态，不创建业务成功事件，不进入规划撤销栈。

1.1.3移除原生Canvas集成：脑图工具栏、甘特项目行与命令面板不提供打开、导出或导入原生Canvas的入口；插件无对应全局桥接或存储接口。后台同步不再创建`.canvas`文件，升级不删除或修改已有文件。项目Markdown直接由结构化节点及执行记录生成；脑图数据继续使用项目节点、线路及独立视口状态。

1.1.2参照本地 `终身岛民-完整无限制版/a-my-island` 1.6.0实际画布实现：规划沙盘与脑图共用相同的锚点缩放计算，范围12%～300%。滚轮以光标为锚点，按像素/行/页归一化并在每帧合并，限制单帧变化，避免触控板微小事件造成跳变；工具栏以视口中心为锚点。双指缩放可同时平移，结束后单指继续平移。“适应画布”根据实际节点包围框居中，不能只重置100%。固定工具栏、导航和输入表单不随内容层缩放。

视口状态保存在完整领域提交的 `viewports.planning` 和 `viewports.projects[projectId]`，值为 `{x,y,zoom}`（局部视口像素和缩放比例）。规划与每个项目分别记忆视口，切换、撤销重绘、保存及重启均恢复各自状态。旧数据无该字段时使用默认视口；非有限坐标或越界比例不得用于渲染。视口属于呈现状态，不产生业务成功事件，不修改执行事实。

脑图路线使用正交绕行，优先避开其他节点；节点移动、尺寸变化、折叠后使用同一算法刷新，不得在重绘与拖拽时切换线路形状。旧路线缺少颜色/粗细/箭头等字段时补全默认样式。线路标签与设置面板放在未缩放的视口层：标签从世界坐标投影定位，字体保持10～15px，可视范围外120px的标签隐藏；标签不得通过位置动画滞后于线路。点击线路或标签、触屏点击标签都可打开设置；面板保持固定尺寸并限制在可视范围内。

连线支持两次点击手柄，也支持鼠标或单指从起点手柄拖到目标节点。拖动显示临时虚线和有效目标描边，松手才创建真实关联；空白、自连、Esc、取消触摸、失焦或切换项目取消预览。临时线不写入edges、历史或Vault，触屏合成点击不能重复建边。有效提交沿用相同的去重、历史和持久化入口。

路线名称、颜色、粗细、虚实线、箭头、上下级方向、关系类型和删除均须保存并支持撤销/重做。方向反转和前置类型变更同步源/目标依赖，不能仅改箭头；双向箭头只是显示方式，不制造循环前置。重复连接同向节点对打开已有路线；切换项目或Esc取消待连接状态。普通关联不纳入子级跟随链。已有重叠节点需先拖开，才能获得清晰的绕行空间。

场馆与建筑来源PAVILION_META，真实数量由项目派生。新场馆保存图标、名称、分类与位置，并恢复建筑、筛选、分类选择器。校史馆/武道馆/思辨馆/修身阁/custom-*统一使用同一项目工作台。

复盘派生的计划日不早于项目开始日；若在项目结束后继续派生，项目结束日延长到新行动的计划日，使派生动作能够实际调度。独立HTML在IndexedDB恢复完成前暂停交互；竖屏使用单列表单，导航不允许挤成逐字竖排。

### 4.3 四大规划场馆的专属语义

| 场馆 | 规划内容 | 执行交付 | 结果回路 |
| --- | --- | --- | --- |
| 校史馆 | 学科目标、知识文本、订正实训、错因复盘 | 规划时长、草稿/订正卷、实测指标、提升行动 | 记录 → 节点/项目 → 随记 → 真实验收后成就 → 回源 |
| 武道馆/兴趣屋 | 技术动作、训练目标、专项练习、动作复盘 | 时长、照片/视频；次数等用数值自定义字段 | 同源训练记录；没有采集热量时不显示卡路里成果 |
| 思辨馆 | 心智模型文本、论题、费曼练习、反思 | 手稿/音视频、论证说明、观点提升行动 | 成果必须在cognition分组显示并精确回源；不生成无依据能力分数 |
| 修身阁 | 原典研读、生活践行、问道与补救 | 原典说明、真实诵读/手抄物证、防守清单、心得 | 问道/裁决的来源ID → 项目 → 执行/结业 → 来源记录与荣誉 |

复杂试卷识别、运动传感器、自动认知评分和智能大模型问答不属于已交付能力，不放假按钮或虚构结果。当前采用通用节点、真实附件与人工录入覆盖上述场景。

### 4.4 问道池与违约补救

困惑由本人输入，经典指引来自明确标识的本地经典语料/关键词规则，不宣称AI推理。保存生成inquiryId。转化按ID幂等：已有linkedProjectId时直接前往原项目；不存在才创建修身项目、节点、首日任务与事件。完成状态根据关联项目验收推导为resolved。

违约入口只在共同签署的公约裁决台。提交必须选择真实clauseId、填写客观事实并确认双方核实；生成violationId并引用familyVersion，扣减履约率5%，派发 **含首尾共7个自然日** 的修身项目。每日践行节点产生7个实例，逐项清单、文字说明按规划核验，补救项目记录sourceViolationId，裁决记录保存remedyProjectId。主查阅法典没有日常打卡入口。

### 4.5 藏金屋

来源为真实收支ledger与账户余额，收入/支出切换只影响表单类型。金额为正、最多两位小数，不允许NaN/Infinity和透支。成功后写交易ID、类别、说明、发生时间、金额与余额，更新看板并产生来源事件，随记可追溯。筛选为ledger投影，不修改账户事实。票据说明与真实附件应区分，不将说明文本宣称为已保存照片。不得与悬赏兑现金额关联。

### 4.6 成就馆

养成类只来自已验收的goal记录或核准悬赏；四大规划场馆与所有custom-*动态分组，不设藏金屋养成柜。每项展示真实日期、指标目标/实测值、附件、来源项目、审核说明。不能自动填“100%达成”“全部合格”。重复归档相同目标不重复铸章。

生活高光可自主新增：类别六选一，标题2～30字，描述20～300字，发生日期不晚于今天，必须保存真实照片原件。附件通过统一服务入库，缩略/全屏/历史均读取同一路径，不能只保存文件名。

档案“定位源项目”必须使用sourceProjectId/sourceNodeId，不以标题或场馆名代替。生活高光没有项目时只回到其日期的随记/事实来源。导出成果档案生成真实Markdown，含实际指标、日期、来源ID和附件链接；没有PDF/纸质证书时不得提示已生成。

### 4.7 个人行为规范与家庭公约

《大学》经典解释属于系统参考资料；家庭条款、姓名、签署时间和版本必须来自FamilyPact。初始未签署状态不能显示虚构姓名、印章或历史日期。维护家庭档案须由双方共同确认后生成新版本，保留旧版本。主查阅页只读已签署条款，裁决引用该版本。公约导出生成真实文件。

本地亲子确认是家庭协作记录，不提供独立家长账号身份认证，也不声称法律防伪/不可篡改。

### 4.8 每日随记

上半轨读取带来源ID的真实DomainEvent；下半轨保存文字、心情、1～5星精力与真实媒体。字数规则统一：任意长度可保存草稿，**30～500字**可封存。启发题按日期轮换。不得用默认60分钟、默认做题数量或默认视频时长填充空数据。

媒体统一存于Vault `attachments/YYYY-MM-DD/`；记录保存路径、类型、原始文件名、上传时间、大小和可读取的实际视频/音频时长；读取失败显示“时长未读取”。草稿与历史共用真实播放器。

同日封存更新当前日期条目并保留版本；跨日先保存最新文字/原件，即使当天已封存过，也不能跳过后清空草稿。只清理新日的临时输入，不删除历史。历史媒体按其ID从归档读取。原始自动流不允许孩子手动改成不存在的执行事实。

### 4.9 亲子悬赏

每条契约独立保存历史，状态published→accepted→redeemed。发布须有主题、非金钱心愿、验收标准、真实createdDate/endDate，期限1～366天。告示倒计时由实际日期计算。

揭榜幂等，并以bountyId生成执行实例。孩子上传挑战真实照片/视频并提交说明后进入待家长核验；上传本身不代表完成履约。家长须填写寄语、勾选核验才可兑现，保存核验人/时间和原件，生成带bountyId的成果及随记事件。换榜不覆盖旧契约，不把当前契约状态应用到所有旧卡。历史可选择查看。

### 4.10 自定义场馆与个性化设置

新场馆注册元数据、项目分类、沙盘建筑与位置，继承统一规划/执行/成就规则。设置数据保存在USER_PROFILE_STATE.settings并导出island_settings.json：背景、昵称/头像、互斥粒子、沉浸区域。设置不是有效成长事件。为避免跨Vault污染，Obsidian不以共享localStorage作为权威来源；独立HTML预览使用独立IndexedDB。

### 4.11 原型工具与插件命令

插入图片必须实际保存附件并创建资料节点；插入表格必须创建可编辑的真实文本表；笔记按钮打开可输入便签。未启用的旧版相机/统计/补卡占位工具禁用并说明，不能提示已产生结果。

插件命令在执行/规划/甘特/脑图/随记之间跳转时保留明确项目上下文；缺项目先提示选择，不落到固定p1。启动行为读取openOnStartup。关闭/切换视图清理监听、动画、计时器，不能影响Obsidian其他标签页。

## 5. 保存、迁移与恢复

### 5.1 目录与权威关系

```text
00_Island_Core/
  domain_state.json                 # schemaVersion=3完整提交：领域实体、edgesByProject、stores
  domain_state.previous.json        # 上次完整版本
  user_profile.json / island_settings.json / island_topology.json
  app_state_snapshot.json           # 会话与旧版兼容缓存，不是页面事实源
01_School_校史馆/                   # dojo/cognition/cultivation及custom同构
  projects.json                     # 带storageRevision的可编辑项目投影
  projects.revision.json            # 索引版本，空列表也能识别旧导出
  02_Projects/nodes_<id>.json        # nodes[]和edges[]；cardsHtml只为兼容缓存
  02_Projects/<title>--<id>.md
05_Treasury_藏金屋/ledger.json
06_Achievements_成就馆/achievements.json
07_Baseline_个人行为规范/family_pact.json
08_Daily_每日随记/journal.json
08_Daily_每日随记/YYYY/YYYY-MM-DD.md
09_Bounties_悬赏公告/bounties.json
10_Custom_自定义场馆/<pavilionId>/...
attachments/YYYY-MM-DD/<unique-file>
exports/                           # 真实公约和成果Markdown
```

完整领域提交先复制状态、串行保存：写入并读回校验pending → 备份有效主档案 → 通过适配器覆盖写入并校验主档案 → 清理pending。不能用`rename(pending, existingPrimary)`替换已有文件，Obsidian会拒绝目标已存在。中断时尽力恢复旧主档案，保留较新的有效pending用于原地重试或重启恢复；损坏主档案只有在存在完整有效pending时恢复，并保留损坏原件，没有有效pending则暂停写入。

stores包含档案、账本、成就、随记、问道、当前悬赏及场馆元数据，边独立保存在edgesByProject。分文件带storageRevision导出；projects.revision.json连空列表也标记版本。恢复先读取完整提交，再读取同版本或更新的项目/节点文件；因此正常外部编辑projects/nodes能生效，旧导出不能回滚较新的提交。其他模块导出不是第二个编辑入口。主档案保存成功但缓存或Markdown导出失败时，明确提示“成长数据已保存，导出待重试”；不得误报主数据未保存。设置显示当前版本、最近保存时间或具体错误，并提供重试保存。

财务、随记、成就、问道及设置导出用于清晰查询；family与记录以完整领域提交为准，Markdown不是隐式标准编辑入口。项目的节点位置与线路由插件自身脑图维护。需要同时编辑多个设备时先依赖Vault同步完成，当前不宣称提供自动语义冲突合并。

### 5.2 旧版迁移

保留旧快照、JSON、HTML卡片和所有执行记录。解析旧cardHtml生成结构化节点，规范枚举与引用。旧记录缺新验收标记时保留为legacyUnverified，不自动制造达标结论。不得按p1～p5、标题或日期前缀删除用户数据。迁移后任务池由领域数据重新生成。原文件与previous备份用于恢复，不静默清理附件；旧版生成的`.canvas`文件保留，由用户自行维护。

### 5.3 双链与事件

Markdown记录实际日期、指标与附件路径，保留执行/节点来源ID、实际专注秒数和项目/随记双链；随记自动事件保留sourceId。悬赏JSON导出items全历史和activeId，恢复后当前悬赏须绑定回同一个领域实体。领域成功事件在业务校验通过后发出；取消、失败、不存在的入口不能发送“执行成功”。window函数包装不是事务，也不能当作成功事实。

## 6. 验收门槛与问题追踪

本版用 `audit/PRD_DESIGN_PLUGIN_CLOSED_LOOP_AUDIT.md` 的D01～D24为反例输入。每项须有修复后的相反断言，并验证重载、跨项目、跨日和重复操作。保留旧报告作为历史证据，新增1.1.0验证记录，不把旧报告覆盖成“通过”。

必须通过：默认日期有效；新项目/复盘派发；空画布清理；历史栈隔离；规划标准强校验；节点进度；统计不依赖DOM；周/月精确任务；逾期按日；归档校验；成果真实实测；源节点定位；真实高光原件；家长寄语/核验；多契约独立；问道幂等；跨日草稿保全；真实插入/导出；领域文件恢复；模板不可变；跨年时间轴；动态成果分组；自定义值读写。

构建和类型检查通过不代替业务验收。浏览器内存适配器验证不代替Obsidian及Android真机验收；发布说明必须准确说明实际已测范围。
